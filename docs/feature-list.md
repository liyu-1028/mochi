# Mochi V1.0 功能清单（Feature List）

> **项目定位**：Mochi —— 会成长的桌面智能伙伴
> **Slogan**：捏出你的专属AI伙伴，让智能体拥有温暖的模样。
> **优先级定义**：P0 = Must Have（首版必须交付，缺一不能上市）；P1 = Nice to Have（首版后迭代，但设计需预留接口）
> **编号规则**：`模块号.序号`，可直接作为需求池/看板卡片 ID

---

## 0. 架构前提（影响功能拆分的关键决策）

在拆功能前，先冻结三条架构假设，各模块验收标准基于此：

1. **桌面壳**：Electron 或 Tauri（推荐 Electron，Live2D Web SDK 生态成熟），角色窗口为透明无边框 Webview。
2. **Agent 后端**：LangGraph（Python）以 **本地 sidecar 服务** 形态随应用启动，前后端通过本地 WebSocket/SSE 通信。**前后端之间只依赖“标准事件协议”，不依赖实现**——这是“任何开发者可挂载自己 Agent”愿景的地基。
3. **数据本地化**：配置、记忆、对话历史默认全部存本地（SQLite + 本地文件），云端仅用于用户自备的模型 API。

## 2. 角色渲染与交互模块（Live2D）

| 编号 | 功能点                  | 优先级 | 验收标准                                                                                                                                    |
| ---- | ----------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 2.1  | Live2D 模型加载与渲染   | P0     | 默认角色渲染帧率 ≥30fps（目标 60fps）；透明背景；常驻空闲时 CPU 占用 ≤8%                                                                    |

| 2.3  | 基础嘴部动画            | P0     | 文本流式输出或语音播放期间口部开合自然，结束平滑闭合                                                                                        |
| 2.4  | 鼠标交互                | P0     | 视线跟随光标；点击头部/身体不同区域触发不同反应动作；拖拽角色可移动落点                                                                     |
| 2.5  | 情绪表情映射            | P0     | 后端响应携带 emotion 标签，角色呈现对应表情，至少覆盖 5 种（开心/难过/困惑/惊讶/不好意思）                                                  |
| 2.6  | 性能护栏与自动降级      | P0     | 高 CPU/GPU 负载或电池模式下自动降帧、暂停非关键动画，恢复后自动还原；降级不影响对话功能                                                     |

| 2.8  | 闲置自主行为            | P1     | 闲置 ≥5 分钟随机播放小动作（伸懒腰/四处张望/打盹）；不打扰用户（不发声、不遮挡操作）                                                        |

| 6.1  | 标准事件协议（前后端契约） | P0     | 定义事件流：`token / thinking / tool_call / tool_result / emotion / state / done / error`；协议带版本号；**第三方 Agent 只要实现该协议即可挂载 Mochi**（长远愿景的技术锚点）                      |
| 6.2  | 对话节点                   | P0     | 多轮上下文对话、流式返回、携带情绪标签                                                                                                                                                            |
| 6.3  | 模型接入层                 | P0     | 支持 OpenAI 兼容接口 / Anthropic / Ollama 本地；Key 本地加密存储；切换模型无需重启；Ollama 未安装时给出引导                                                                                       |
| 6.4  | 记忆技能                   | P0     | 会话内短期记忆 + 跨会话长期记忆（本地 SQLite + 向量索引）；自动沉淀用户偏好与关键事实并可被召回；用户可查看/编辑/删除任一条记忆（隐私可控）                                                       |

| 6.7  | 错误处理与优雅降级         | P0     | Key 错误/网络失败/模型过载给出引导文案而非堆栈；连续失败自动建议排查步骤                                                                                                                          |
| 6.8  | 内置技能包：联网搜索       | P1     | 搜索并总结，附来源引用；可一键开关                                                                                                                                                                |
| 6.9  | 内置技能包：文件小助手     | P1     | 读取/总结指定文件、按规则整理文件；所有危险操作走 6.5 确认机制                                                                                                                                    |
| 6.10 | 内置技能包：日程提醒       | P1     | 自然语言设置提醒（“30分钟后提醒我喝水”），准时通知 + 角色动作/语音提示                                                                                                                            |
| 6.11 | 技能编排可视化             | P1     | 设置中开关/简单串联技能节点（“乐高式”拼接）；提供 ≥3 个模板                                                                                                                                       |

## 10. 关键风险提示（架构师视角）

1. **6.1 事件协议是全项目的“宪法”**：建议 M0 阶段就冻结 v0.1 并写成公开文档。它同时决定“角色表现力上限”（2.2/2.5 的输入源）和“第三方 Agent 挂载”的愿景能否兑现，后期改动成本极高。
2. **“图片即皮肤”（3.4）是传播爆点也是质量风险**：静态图的动态效果若太廉价（纯平移缩放）会反噬“有温度”的定位，建议 M1 阶段安排专项打磨（漂浮+呼吸+微交互的参数调优），宁缺毋滥。
