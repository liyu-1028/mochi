> **项目定位**：Mochi —— 会成长的桌面智能伙伴
> **Slogan**：捏出你的专属AI伙伴，让智能体拥有温暖的模样。
> **优先级定义**：P0 = Must Have（首版必须交付，缺一不能上市）；P1 = Nice to Have（首版后迭代，但设计需预留接口）
> **状态图例**：✅ 已交付 · 🚧 部分交付 · ⬜ 未开始
> **编号规则**：`模块号.序号`，可直接作为需求池/看板卡片 ID
> **文档状态**：2026-08-06 更新（当前版本 v0.2.1；人格功能 6.13/7.9 已合入主干、待随版本发布）

## 0. 架构前提（已冻结决策）

在拆功能前，先冻结三条架构假设，各模块验收标准基于此。截至 2026-08-06（v0.2.1）的实现回退，决策过程见 `docs/internal/adr/0001-tech-stack.md`：

1. **桌面壳**：**Tauri v2**（初版方案曾倾向 Electron，后为「轻量常驻伙伴」的产品气质转向 Tauri——安装包/内存显著更小、原生托盘与系统 API 成熟），角色窗口为透明无边框 Webview；前端 React 19 + TypeScript + Vite，渲染核心 pixi.js + pixi-live2d-display；功能面板（设置/回忆/衣橱）为**独立 WebviewWindow**（注意：窗口间前端状态不共享，联动须经 Tauri 事件桥接）。
2. **Agent 后端**：Python **FastAPI sidecar** 随应用启动，前后端经本地 WebSocket/REST 通信；当前对话管线为自研轻量实现，**LangGraph** 计划随工具框架（M1-S4）引入。**前后端之间只依赖“标准事件协议”（v0.1 已冻结，见 `docs/protocol/agent-events-v0.1.md`），不依赖实现**——这是“任何开发者可挂载自己 Agent”愿景的地基。
3. **数据本地化**：配置为 TOML（config.toml，原子写入）、历史为本地 SQLite；**API Key 只进 OS 钥匙串（key_ref 引用，永不落明文）**；云端仅用于用户自备的模型 API。

## 8. 非功能基线（上市红线，逐项验收）

| 维度 | 指标                                                    |
| ---- | ------------------------------------------------------- |
| 性能 | 常驻内存 ≤600MB；空闲 CPU ≤5%；角色窗口 ≥30fps          |
| 稳定 | 连续运行 72h 无内存泄漏；sidecar 断连自动重连，对话不丢 |

## 10. 关键风险提示（架构师视角）

1. **6.1 事件协议是全项目的“宪法”**：建议 M0 阶段就冻结 v0.1 并写成公开文档。它同时决定“角色表现力上限”（2.2/2.5 的输入源）和“第三方 Agent 挂载”的愿景能否兑现，后期改动成本极高。（现状：v0.1 已于 M0 冻结，后续只宽松新增。）
2. **“图片即皮肤”（3.4）是传播爆点也是质量风险**：静态图的动态效果若太廉价（纯平移缩放）会反噬“有温度”的定位，建议 M1 阶段安排专项打磨（漂浮+呼吸+微交互的参数调优），宁缺毋滥。
3. **跨窗口状态隔离是隐性陷阱**：功能面板运行在独立 WebviewWindow，各窗口前端状态（zustand）互不共享；任何跨窗口状态联动必须显式经 Tauri 事件桥接，否则出现“单窗口生效”的错觉缺陷（实战案例：回忆面板删除活跃会话后主界面气泡未清空，2026-08-06 已修复）。此类 GUI 行为单测难以覆盖，改动须从终端启动实测验证。
