# Mochi 产品功能全貌（V1.0 路线图）

> **项目定位**：Mochi —— 会成长的桌面智能伙伴
> **Slogan**：捏出你的专属 AI 伙伴，让智能体拥有温暖的模样。
> **优先级定义**：P0 = 首版核心能力；P1 = 后续迭代能力
> **状态图例**：✅ 已完成 · 🚧 部分完成 · ⬜ 未开始 · ➖ 已移除／不再规划
> **编号规则**：保留既有 `模块号.序号`，新增功能顺延，供需求池与看板引用
> **更新日期**：2026-10-18；应用版本基线 v0.15.1，状态包含当前主干中尚未发布的变更

本文以当前仓库实现为准；“已完成”表示对应功能已实现，不表示所有平台的性能、稳定性指标均已验收。版本发布范围见 [CHANGELOG](../CHANGELOG.md)，非功能目标单列于 §8。

## 0. 产品方向与架构

1. **角色渲染统一使用 VRM**：Three.js + `@pixiv/three-vrm`，角色为 `.vrm`，肢体动作使用 `.vrma`。VRM 0.x / 1.0 加载、角色导入与动作管理已完成。**后续不再使用或扩展 Live2D**，静态图片角色也不属于当前产品路线。仓库仍存在旧 Live2D 渲染、导入与构建依赖，清理状态见 3.10，不能将路线调整等同于代码已全部移除。
2. **桌面壳**：Tauri v2；React 19 + TypeScript + Vite；透明无边框角色窗口。设置、回忆、装扮与动作管理使用独立 WebviewWindow，跨窗口联动通过 Tauri 事件桥接。
3. **Agent 后端**：Python FastAPI sidecar 随应用启动，**LangGraph 对话与工具编排已完成接入**。前后端通过本地 WebSocket / REST 及[标准事件协议 v0.1](protocol/agent-events-v0.1.md)通信；协议保留第三方 Agent 接入空间，现阶段尚无完整接入产品界面。
4. **数据与语音**：配置 TOML、会话／记忆 SQLite、角色与动作文件存于本机；API Key 存 OS 钥匙串。云端模型会接收相应对话内容；当前 TTS / ASR 使用阿里云百炼，需要配置连接。**语音播放默认关闭**，配置后手动开启；全本地语音与一键离线隐私模式尚未完成。

当前表现边界：

- 动作词表表示可识别的用途，不代表默认拥有全部动作素材。AI 提示仅提供已配置且允许 AI 使用的语义动作；自定义命名空间动作可预览或待机播放，尚不能直接由 AI 标记选择。
- 回答中的显式动作／表情节拍目前依赖 TTS 播放上下文；关闭语音、静音或合成失败时，缺少纯文字时序回退，相关节拍会等待至过期。位置通道保留流程不等于当前有可用的位置指令。
- 一对中文括号目前只取一个匹配项；无显式表演事件时，才在回复结束后进行整体情绪分类。

## 10. 产品约束与继续开发时的核对点

1. **只沿 VRM 路线扩展角色能力**：新增角色、动作和交互以 VRM / VRMA 为准，不再新增 Live2D 功能。清理旧实现时仍需保留实际使用资产的许可与署名记录。
2. **动作能力必须与素材一致**：未配置动作时保持自然站姿；不得把动作词表、用途名称或旧 Live2D 包络当作当前 VRM 已具备的肢体动作。
3. **区分当前主干实现与已发布版本**：百炼语音、语音输入及最近的位置指令移除等变更已在代码中实现，是否随发行包交付以对应版本的 CHANGELOG 为准。
4. **跨窗口状态显式同步**：独立 WebviewWindow 的前端状态不共享；切换会话、角色、配置或音频设置时，必须同时验证主角色窗口和功能面板。
5. **标准事件协议保持实现解耦**：角色通过状态、情绪与 `character.cue` 消费 Agent 输出；保留接口不等于已有完整第三方 Agent、提醒或插件产品。
