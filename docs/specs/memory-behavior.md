# 用户记忆的持久化与对话召回

记忆由 `SessionStore` 保存在应用数据目录的 `mochi.db`，与聊天会话分别管理。
手动添加、编辑、删除通过 `/memories` API 提交后立即生效；切换会话或重启应用
不会丢失已保存的事实与偏好。完整对话后的自动提取在后台运行，可由
`[memory].auto_extract` 关闭；提取失败不阻塞回复，每日自动新增上限为 20 条。

`MemoryManager.recall_for_prompt` 每回合重新读库，提供用户背景及本轮相关信息。
偏好不再要求问题与记忆内容共享关键词；例如记录“回答要活泼幽默”后，问
“我的个人偏好是什么？”也会得到这条背景。手动记录优先，其次是自动提取的偏好，
再补充其他事实；已保存的第一人称内容中的“我”明确指用户。

为控制上下文，先保留最多 10 条手动记录/偏好，再补充最多 5 条关键词命中，
最后用其他用户背景补足。去重后最多 20 条、2000 个字符，并由 Agent 根据模型
窗口进一步限制为可用上下文的三分之一。超预算的条目不截断改写；全部记忆仍
留在数据库中，可在记忆管理查看。模型应根据问题使用资料，询问偏好时直接
说明已记录内容，不猜测未记录的信息。

验收覆盖：手动添加后新会话召回、API 保存后重建应用、编辑/删除即时生效、
较旧偏好不被新事实挤掉、关键词补充、条数/字符/模型窗口预算及自动提取落盘。
